# Project instructions

Read this file and [handoff.md](handoff.md) before changing code. Inspect the working tree and preserve user edits. Field Scoreboard is a standalone MIT project; do not modify Field Timer or share its configuration/port. Keep this filename uppercase; never add a conflicting `agents.md`.

## Scope and source map

Go 1.23+, standard-library runtime, embedded HTML/CSS/JavaScript, CGO-free Windows x64 GUI/console and Linux x64 CLI. Default address: `127.0.0.1:8790`. See [architecture](docs/ARCHITECTURE.md) for ownership/API boundaries and [CONTRIBUTING.md](CONTRIBUTING.md) for portable commands and dependencies. No paid dependencies, accounts or external services are required to run the application.

## Behavior to preserve

- **Touch at every width and pointer type:** all selectors use the large choice dialog; hidden native selects add no keyboard stops. Keep keyboard navigation, focus restoration, scrolling without accidental selection and dynamic option synchronization. Small-screen Menu preserves drafts and shows the current page.
- **Consistent numeric controls:** shared labelled groups, approximately 64 px buttons/fields, 28 px numbers and visible gaps; stack instead of shrinking. Scores/fouls/period apply immediately and allow exact entry. Duration edits wait for Set. Match 5/8/10/12/20-minute presets edit only pending Minutes/Seconds (seconds 0); matching drafts highlight. Preserve direction/format/custom entry and OCR guards. Shot presets remain immediate. Preserve zero minutes, second carry/borrow, validation and polling-safe unfinished drafts. **No sliders.**
- **Clock panels:** title/status/time, transport controls, exactly −5s/−1s/+1s/+5s. Shot then shows Duration presets / Applies immediately, 14s/24s/30s and the resume explanation directly beneath. Divider/Clock setup follows, with Seconds, Output format and Auto-hide; full-width blue Set last. Match retains its pending duration presets above Set. Identical quick targets use 2×2 when needed; numeric steppers remain one-unit. Formats apply immediately, duration/direction wait for Set. Preserve shot presets/auto-hide, the separate Both clocks box and final OCR section.
- **Live team names:** full-width inputs at least 64 px high, 24 px text and bold 20–22 px labels with visible gaps/focus borders at every width. Scope styling to controls, never overlay names. Preserve 32-character input limit, trim/empty validation, commit-on-change and active typing/caret through polling. Names remain editable when scores/fouls follow OCR.
- **Clocks:** Go owns two independent monotonic clocks. Combined Start/Pause keeps times. Shot Reset/Set/presets resume only if the main clock is running, never changing the main clock. Restart returns both clocks to Ready, retaining configuration and game values. Add regression coverage whenever timing logic changes.
- **Game state:** scores 0–999, fouls 0–30, periods 1–20. Period format (number/ordinal/quarter) defaults to number for legacy config, persists outside Layout/presets, and changes neither numeric period nor OCR ownership. Format labels centrally, including 11th/12th/13th. OT overrides the label and preserves number/format; reset game clears OT but keeps the format. Optional shot auto-hide is visual only (shot >= remaining match time or match expired); count-up remaining time uses duration minus elapsed. Never change clock state to hide output.
- **Layouts:** logical 1920×1080 coordinates; browser resizing changes presentation only. Drag deltas account for preview scale. Fine-position arrows use 5/10/20 px, default 5; X/Y ± remains 1 px. Anchor bounds remain X 0–1920 and Y 0–1080. Canvas keyboard arrows remain 1 px / Shift+10 px. Layout/profile changes must not overwrite live scores or clocks.
- **Element transforms:** optional scale_x/scale_y/lock_aspect, .05–20; nil keeps legacy OBS output. Scale actual text and foul dots; retain scaling as values grow, with no fixed content clipping box. Logical 1920×1080 anchors and pointer deltas, 56 px editor-only handles (four corners; unlocked side handles) only in explicit Free transform mode. Default normal selection/dragging uses a thin outline; hidden handles must have no hit area or keyboard stops. Done transforming, another element, background editing, leaving the editor and reload exit the mode without saving/discarding/resetting drafts. Keep numeric controls available in normal mode, mutually exclusive background/field selection and clear label. Keep shared editor/preview/OBS geometry, width/height ± drafts, fonts/alignment/visibility, Save/Discard, presets and deep-copy persistence. No sliders.
- **Font picker:** keep Bold in a dedicated pinned row outside the scrolling font list, with a large accessible switch that does not close the dialog. Closed Font shows family and Bold/Regular. Family/weight edits preserve each other and use the selected layout draft, Save/Discard and presets. Hidden rows must not add tab stops to other dialogs.
- **Backgrounds:** new imports default to centered Fit with aspect lock. Sizing has four visible buttons (Fit entire image, Fill canvas, Original size, Stretch to canvas) with prominent labels/help, balanced 2×2 layout and natural narrow stacking. Reflect the draft mode with selected green color/border/checkmark; Custom sizing is a separate status with no active preset. Keep aspect lock and numeric controls below. Preserve existing sizing calculations and Save/Discard/profile restoration; preview/OBS use saved layout. Store original bytes and logical transforms; retain legacy stretch when transform metadata is absent until the background is explicitly edited. Explicit **Edit background — move & resize** / **Finish editing background** selection prevents moving fields. Shared rendering keeps image proportions, clipping and transparency identical in editor/preview/OBS, with handles only in the editor. Imports/removals and numeric edits obey Save/Discard and polling protection.
- **Live display preferences:** foul styles and dot maximum live in Foul indicators, below the preview on desktop and after primary controls/before OCR when narrow; clock formats live in the respective Clock setup sections. Apply/persist immediately without changing game state, clocks or OCR ownership. Preserve their existing Layout/preset schema. Editor Save merges the latest preferences atomically (`preserve_display=1`); Discard/position reset preserve them. Preference updates must never save/discard unrelated geometry. Explicit preset loads retain legacy appearance semantics. Keep Period format beside Period/OT and outside Layout/presets.
- **Editor toolbar:** selection/status above, Free transform left and background edit right, equal large targets, mode-specific help below; stack in that order. Inspector DOM/tab order: clocks/period, home name/score/fouls, away name/score/fouls. Top actions: Restore Defaults, Discard, Save Layout. Preserve the existing element-position/size/transform reset scope. Put coordinate/anchor help immediately below X/Y and above Fine position. Layout profiles has its own full-width card below both editor columns. Match desktop card edges with content-driven grid stretching; stack naturally at narrow widths. Save/Discard stay separate from mode controls.
- **Persistence:** keep config schema compatibility and optional-field defaults. Presets hold layout/graphic references only. Validate PNG/JPG/WebP (15 MB and 8192 px/side limits), hash-derived filenames and safe profile names; reject arbitrary paths/SVG. Never package personal graphics or local configuration.
- **Authentication:** default loopback; remote control/full state requires bearer auth. Token retrieval/rotation, interface discovery and full-state SSE are host-only. Rotation requires JSON and immediately revokes the old token. Read-only remote OBS is allowed only with the active LAN listener and permitted private IPv4 clients, using sanitized state/events without secrets or network settings. Static assets are not a confidentiality boundary. Never put tokens in URLs, logs, public pages or packages.
- **Network UX:** changing listen mode/port requires restart. Display a real selected private adapter IP, not wildcard `0.0.0.0`; do not install firewall rules. Keep local/LAN OBS URLs in the one OBS panel and local token copy/rotation there. Companion uses the separate HTTP Builder, with no dedicated plugin or live feedback promises.
- **ScoreSight OCR:** entire section stays last in Live control, after every manual panel and before footer, at every width/state; no opening/polling focus or scroll jumps. Separate Connect/Disconnect actions use backend connection state, with red/amber/green status text in the top-right badge. Disable duplicates; allow Disconnect during OCR following and source I/O. Cancel polling, invalidate the connection generation, retain values/settings and pause owned clocks when releasing all fields. Reconnect/explicit retry never restores ownership or starts clocks; independent manual clocks remain unchanged. Connection never implies following or camera freshness. One connection/worker, seven independent mappings (main, shot, home_score, away_score, home_fouls, away_fouls, period). Suggest Time/Shot Clock/Home Score/Away Score/Home Fouls/Away Fouls/Period only when actually present; explicit unconfiguration must stick. Per-target large selector, recognised/accepted values, warnings, Follow/takeover; shared connection/freshness once.
- **OCR ownership/validation:** accept only Success/SameNoChange and strict valid target values; never clamp, extrapolate or clear missing/rejected/disconnected data. One bad field must not block others. OCR clocks stay held; takeover retains paused time and invalidates that target’s in-flight responses without blocking other targets. Manual/API commands respect ownership; combined actions reject atomically if either clock follows; game reset rejects atomically if any score/foul/period follows. Fouls accept 0–30 and periods 1–20 independently. Period OCR accepts full numeric, correct ordinal and Q-prefixed values in 1–20, ignoring case/surrounding whitespace only for period. Never extract digits from arbitrary text. Preserve raw Recognized and canonical numeric LastAccepted. Numeric period OCR preserves OT; the explicit OT switch remains manual and reveals the latest accepted number in the selected format when off. Do not infer match running status from OCR; manual shot reset stays Ready during match OCR. Auto-hide uses both effective values.
- **OCR persistence/security:** save address/mappings (migrate test.9 field); changed scores/fouls/period use existing game persistence, clocks/observations/ownership do not persist. Restart manual/Ready/disconnected. No source heartbeat exists in observed v0.4.3 /json: cached HTTP success never proves live video. Preserve bounded requests, per-target revisions, authentication and sanitized overlay boundaries. No sliders.
- NDI, direct OBS control and automatic sport rules remain future work. v0.1.0 is the operator-accepted normal release; OCR is included, with video freshness still unverified.

## Required checks and delivery

1. Reproduce the issue and use targeted tests where behavior changes. Never claim hardware tests passed from browser emulation.
2. Run `go test ./...`, `go vet ./...`, and `go test -race ./...` on Linux with a C compiler; run `node --check` for every embedded JavaScript file.
3. Run `python scripts/test_ui_offline.py` for UI changes. Check 375/500/1000/1440/1920 px, touch/mouse/keyboard, 200%/400% zoom, drafts, focus, dynamic options, duplicate IDs and overflow. Inspect narrow/desktop screenshots including 1920×1080.
4. After image/editor changes, run `python scripts/test_background_ui.py <native-binary>` (Playwright/Pillow). Preserve Save/Discard, legacy layouts, aspect lock, profiles and shared rendering.
   For clock-panel changes run `python scripts/test_clock_ui.py <native-binary>` and the Go clock adjustment tests (all four deltas, boundaries, transport, ownership and setup/format separation).
   For team-name control changes run `python scripts/test_team_names_ui.py <native-binary>` for sizes, entry/validation, polling/caret protection, OCR availability and unchanged overlay styling.
   For display/toolbar changes run `python scripts/test_display_ui.py <native-binary>` for immediate output, queued writes, layout-draft isolation, presets, restart and responsive/keyboard order.
   For element changes run `python scripts/test_elements_ui.py <native-binary>` (all nine elements, values/dots, anchors, touch/zoom, drafts, presets and matching OBS geometry).
   For font/picker changes run `python scripts/test_font_ui.py <native-binary>` for family/weight independence, pinned scrolling, keyboard/focus, drafts, profiles, restart and shared rendering.
   For OCR changes also run `python scripts/test_ocr.py <native-binary> --ui` and the Go OCR tests. Use `--live-address http://127.0.0.1:18099` for an isolated read-only live-source check; distinguish it from simulated pause/reset/failure tests. Never manipulate another application's live state without authorization.
5. Build Windows GUI/console and Linux x64 with `scripts/build.ps1` or `bash scripts/build.sh`. Test extracted native packages using `python scripts/test_http.py <native-binary>` on each OS. Linux has no tray. Run `python scripts/test_http_transport.py <native-binary>` for connection-close action bodies; preserve bounded body consumption and never mask transport regressions with retries.
6. Update user/developer documentation, handoff, release notes and verification evidence. For documentation-only repackaging, valid evidence for unchanged source/executable bytes may be reused; explicitly distinguish reused checks from new checks. Preserve tested executables rather than rebuilding unnecessarily.
7. Package using `python scripts/package.py`; run `python scripts/verify_packages.py` and `python scripts/check_docs.py`. Scan the exact source publication and expanded archives for secrets, local data and personal paths. Verify ZIP integrity and SHA-256. No generated binaries, caches or temporary environments in Git.
8. Publish only when authorized by the owner. The owner accepted v0.1.0 and authorized its normal public release. Future publication needs its own authorization. Build fresh binaries for new versions, integrate tested source into main without force-pushing, and never overwrite an existing release/tag. Preserve earlier releases/assets and unrelated remote work unless the owner explicitly authorizes a scoped removal. For v0.1.2 (superseding the planned v0.1.1 publication), only after visual acceptance, publish it as Latest and verify public downloads, then delete the v0.1.0 release entry/assets; preserve its tag, commit history and local archives. Preserve local v0.1.1 commit `52f3458` and its packages. No publication or deletion during this review pass. Verify public access and downloaded asset hashes after publication. Record physical touchscreen, Windows tray, LAN/Companion and live-event checks separately from automation and user-reported smoke tests.
